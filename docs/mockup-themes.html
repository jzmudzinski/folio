Osiem starter themes, ta sama notatka

Hybrid model: CSS variables + utility classes (visual baseline) + prompt addendum (guidance dla agenta jak strukturyzować body_html dla danego mood). User extensible — drop folder, dostań theme.

ADR-020 8 starter themes 2026-05-11

00 Jak działa theme system

Theme to folder w ~/Folio/themes/<name>/ z dwoma plikami: theme.css (visual) + theme.md (prompt addendum). Skill dynamicznie wkleja addendum do system prompta gdy generuje notę dla danego theme'u.

Dlaczego hybrid (CSS + prompt) zamiast tylko jednego

  • Tylko CSS: Agent generuje to samo body. Brutalist i Newsroom wyglądają inaczej, ale struktura identyczna. Newsroom chciałby prose-forward + drop caps; Brutalist chciałby ALL CAPS + krótkie zdania. CSS sam tego nie wymusi.
  • Tylko prompt: Agent kreatywnie generuje strukturę, ale CSS nie zapewnia baseline'u → noty tego samego theme'u wyglądają nieprzewidywalnie.
  • Hybrid: CSS = twarda baza (kolory, fonty, spacing). Prompt = strukturalne decyzje (jakie tagi, jakie listy, jaki ton). Razem = spójność wewnątrz theme'u + różnorodność między.

Wybór theme'u

  • Domyślny user-wide: folio config set theme <name>
  • Per-thread override: folio.create({ ..., theme: "newsroom" }) w MCP
  • Skill może zaproponować: „to long-form research, Newsroom byłby lepszy — przełączyć?"
  • Custom user theme: drop ~/Folio/themes/myown/ z dwoma plikami i Folio go pickupuje

01 Galeria — ta sama notatka, 8 estetyk

Treść identyczna: research-style „RAG vs Fine-Tuning" w 80 słowach. CSS i prompt addendum tworzą różnicę. Rozwiń „Prompt addendum" w każdym, żeby zobaczyć co Skill każe agentowi dla danego theme'u.

Prompt addendum 
Theme: Folio (default)

Voice: precise, opinionated, occasionally snarky. Polish OK.
Structure: bullet-friendly, dense, scorecards for comparisons.
Use utility classes: .eyebrow, .pill, .card, .verdict, .stat
Typography: short headings (2-5 words), no fluff.
Lead: 1-2 sentences max, set the stakes.
Color metaphors: success=good (green), failure=bad (red), warning=mid (amber).
Avoid: emoji storms, "It is important to note", corporate hedging.
Numbers > vague claims always.

02 Implementacja — co dodajemy do planu

Nowy ADR-020

  • Hybrid theme system: CSS variables + utility classes + prompt addendum.
  • Folder per theme: ~/Folio/themes/<name>/{theme.css, theme.md}.
  • Bundled 8 starter themes (te które tu widzisz).
  • User-extensible — drop folder, gotowe.

Update w sprintach

  • S2 Templates: bundle 8 starter themes (CSS + prompt.md) zamiast jednego theme.css. Test każdego z sample noty research/comparison/technical.
  • S3 MCP: folio.create({ theme?: string }) param. folio.list_themes() tool. Default z config.
  • S4 Skill: Skill dostaje listę dostępnych themes + przykład kiedy który zaproponować. Pre-create może spytać: „long-form, użyć Newsroom?". Po wyborze: inject theme.md jako prompt addendum.
  • S7 Polish: theme switcher w viewerze (re-render z innym theme'em dla hosted profile).

Token cost

  • Skill prompt rośnie o ~150-300 tokenów (aktualny theme.md). Akceptowalne.
  • Hosted profile (ADR-012) zostaje — agent generuje semantykę, theme.css aplikuje styl per current theme. Token-saving claim wciąż 40-60%.
  • Standalone build (ADR-012) inline'uje aktualnie wybrany theme. Każda publikacja = freeze theme'u w momencie publish.

Edge case: zmiana theme'u post-create

  • Hosted profile: trivial — viewer renderuje notę z nowym theme.css. Struktura HTML działa, kolory/fonty się zmieniają.
  • Standalone: wymaga rebuild → re-inline nowego theme'u. Możliwe via folio render <id> --theme=<new>.
  • Cloud published: immutable (ADR-013, ADR-018) — istniejący URL zachowuje oryginalny theme. Nowy theme = nowa publikacja.
  • Pitfall: Skill addendum specyficzny dla theme'u mógł kierować strukturą HTML. Notę zrobiona pod Brutalist (krótkie zdania, ALL CAPS headings) wygląda dziwnie w Pastel. Switching post-create działa kosmetycznie, ale „natywnie zmieniony theme" = re-create.

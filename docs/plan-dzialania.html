📄 Folio · Plan Działania

Wizualna powierzchnia komunikacji między AI a człowiekiem

Markdown nie unosi diagramów, scorecardów, color-codingu ani in-page nav. Folio = standalone HTML jako medium *bieżącej* rozmowy z agentem. Nie KB — komunikacja.

Status: Planning v3.1 2026-05-11 MVP = S1+S2+S3+S4 Validated by Thariq (Anthropic)

01 Skrót

Agent (Claude/Cursor/Ryszard/GPT) ma ci coś przekazać — research, porównanie, raport. Dziś idzie markdownem do terminala. Folio wpina w pętlę: agent generuje wizualnie bogaty HTML → ląduje w lokalnym folderze → otwierasz w przeglądarce → opcjonalnie publikujesz na folio.app/<user>/<slug> dla wybranych odbiorców.

Każdy klient MCP (Claude Desktop, Cursor, OpenClaw, Continue) pisze do tego samego Folio. Append-only — chcesz inną wersję, agent tworzy nowy dokument obok poprzedniego w tym samym threadzie. Stare nieoznaczone czyszczą się po 30 dniach. Publish auto-finalizuje.

🎯 W jednym zdaniu

Folio robi z formatu HTML medium komunikacyjne między agentami a człowiekiem — pierwszą warstwę gdzie agent może pokazać, nie tylko opowiedzieć.

02 Problem → Rozwiązanie

Problem

Markdown jest flat

Brak scorecardów, sidebarów, color-codingu, in-page nav, interactive widgets. Renderowanie zależy od narzędzia.

Problem

Artifacts są zamknięte

Claude Artifacts żyją w Claude UI — agent-locked. Notion AI = Notion-locked block format. Brak agent-agnostic medium.

Problem

Share UX kuleje

Markdown → renderer-of-the-day → screenshot do Telegrama. Brak pojedynczego linku z bogatym preview.

Rozwiązanie

Standalone HTML

Thariq pattern — self-contained pliki działają wszędzie. Theme.css inline, jeden dokument = jedna jednostka komunikacji.

Rozwiązanie

MCP-native

Każdy agent z MCP może pisać do Folio. Te same tools dla Claude'a, Cursora, Ryszarda, GPT. Local-first.

Rozwiązanie

Publish + OG preview

`folio.publish` → URL + auto-generowany screenshot jako OG image. Rich preview w Telegram/Slack/iMessage.

04 Demo flow

folio · agent loop 
# 1. User prosi agenta o research
USER › Przygotuj research o RAG vs fine-tuning

# 2. Agent zna stylebook i MCP, wybiera istniejący thread (lub tworzy)
AGENT › folio.suggest_thread({ title: "RAG vs Fine-Tuning" })
       → []   # nic podobnego, nowy thread
AGENT › folio.create({
         type: "research",
         title: "RAG vs Fine-Tuning",
         body_html: "<article>...</article>",
         thread_id: "rag-vs-finetuning",
         theme_profile: "hosted"          # -50% tokenów
       })
       → { id: "01HN...", local_url: "http://localhost:4810/n/01HN..." }

# 3. User otwiera link, czyta, prosi o iterację
USER › Cost analysis za płytkie. Konkretne ceny + case studies.

# 4. Agent NIE edytuje. Tworzy nowy dokument w tym samym threadzie.
AGENT › folio.create({ ...thread_id: "rag-vs-finetuning" })
       → { id: "01HP...", thread_siblings: ["01HN..."] }

# 5. User wybiera v2, klika "Mark as final" w viewerze
# 6. User publikuje — auto-final, OG screenshot generowany w tle
USER › Wyślij Magdzie i Łukaszowi

AGENT › folio.publish({ id: "01HP...", audience: ["magda@…","lukasz@…"] })
       → { url: "https://folio.app/jarek/rag-vs-finetuning-deep" }

# 7. Magda dostaje magic link → Telegram pokazuje rich preview z OG image

05 Filary projektu

P-01

Append-only

Agenty tylko CREATE — nigdy nie edytują. Inna wersja = nowy dokument w tym samym thread folder. (ADR-014)

P-02

Local-first, cloud opt-in

Wszystko żyje w ~/Folio/. Cloud (folio.app) to osobny projekt, nie blokuje MVP. (ADR-013)

P-03

Auto-cleanup ~30d

Nieoznaczone noty znikają po 30 dniach. Publish auto-finalizuje. Folio nie staje się cmentarzyskiem slopu. (ADR-015, ADR-019)

P-04

Token-aware

Dwa profile renderu: hosted (-50% tokenów via shared theme) i standalone (do publish/share). (ADR-012)

P-05

Anti-Clippy gating

Skill surface'uje wygasające noty TYLKO w Folio-related kontekście. Hard rules. (ADR-019)

P-06

Pomiar od dnia 1

Token count, class match rate, lifecycle metrics w SQLite od S1. Walidujemy 50% token claim, nie wierzymy. (ADR-017)

06 Walidacja zewnętrzna

"HTML is the new markdown. I've stopped writing markdown files for almost everything and switched to using Claude Code to generate HTML for me."

— Thariq Shihipar, Claude Code @ Anthropic · 2026-05-08

Folio NIE jest contrarianem. Wewnątrz Anthropic to już default workflow dla planów, code reviews, design systemów, raportów. Thariq opublikował 20 standalone HTML-i jako proof. Folio formalizuje ten pattern: dodaje strukturę folderów, viewer, search, share. Pivot z 2026-05-11 koryguje wcześniejsze założenie „long-term KB" na właściwe „medium komunikacji".

08 Wątpliwości warto trzymać w głowie

  • 50% token claim wymaga pomiaru. Hosted profile redukuje tokeny tylko jeśli LLM konsekwentnie używa klas z theme.css, nie inline style="". Walidujemy w S2 telemetrią.
  • KB creep przez ADR-019. Skill ze stanem cross-session lekko zaprzecza „nie KB". Gating jako reguła #1 w SKILL.md — pierwsze co retro'wujesz, jeśli pojawi się Clippy.
  • Bun + MCP SDK compatibility. Smoke test w S0 przed S3. Plan B: Node z bun-compatible CLI.
  • Mobile selection / sharing UX. Real users dostają linki na phone, czytają na phone. Responsive nie jest miłym dodatkiem.
  • Multi-agent w tym samym Folio. Dwa agenty piszą równolegle do tego samego threadu — eventual consistency wystarczy w append-only, ale warto przetestować.

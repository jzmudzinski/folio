# Handoff: Folio Viewer Chrome v2

## Overview

Redesign of the **viewer chrome** for [Folio](https://github.com/...) — the local web UI (`http://127.0.0.1:4810`) that lets a human browse HTML notes generated by AI agents. Scope: the four viewer states (note list `/`, search `/search`, thread index `/threads`, single note `/n/:id`) plus the sticky top bar and filter strip that wrap them. **Out of scope: note content rendering** — that is handled by the 8 themes in `themes/<name>/theme.css`. Do not touch those.

Pain points this redesign solves (verbatim from the user brief):

1. 🔴 List felt undifferentiated — everything weighed the same visually
2. 🔴 Narrow theme wrap (720–960px) looked like a cropped page on 1400px+ screens
3. 🟡 Sidebar in note view was heavy; primary action ("Mark as final") drowned in metadata
4. 🟡 Search results — threads vs notes looked like the same kind of thing
5. 🟡 Static, no micro-interactions
6. 🔴 Mobile was untested

## About the Design Files

Files in `design/` are **design references created in static HTML** — a working prototype showing the intended look and behavior. They are **not the production code to ship**. The Folio viewer is server-rendered Bun.serve output where the whole CSS lives as a `VIEWER_CSS` const inside `src/viewer/render.ts` and HTML is produced by template literal functions (`pageList`, `pageSearch`, `pageThreads`, `pageNote`).

**Task: port `design/viewer.css` into `VIEWER_CSS` in `src/viewer/render.ts`, and update the HTML-generating functions to emit the markup structure shown in `design/index.html` for each route.** No framework introduction. No build step. No icon library. Vanilla JS only if absolutely needed (the prototype's route switcher is dev-only and not part of the production output).

## Fidelity

**High-fidelity.** All colors, type sizes, spacings, borders, transitions are final and intentional. Recreate pixel-perfectly. Where this conflicts with the existing `render.ts`, the design wins; rewrite the template literal.

## Files in `design/`

| File | What it is |
|---|---|
| `index.html` | **Master prototype.** All 4 routes as `<section class="route">` blocks, toggled by a dev-only switcher fixed at bottom-center. Each route is wrapped in `<section data-route="list|search|threads|note">`. Open in browser, click switcher to navigate. |

## Routes

### 1. `/` — note list

**Purpose:** primary entry. User scans recent notes, jumps to one, filters by type/status.

**Layout:**
- Sticky top bar (1400px max content width, `--gutter` 32px sides)
- Filter strip below (same width)
- `<main class="v-page">` — `max-width: 1100px`, centered, `padding: 28px var(--gutter) 96px`
- Inside `v-page`: one or more `<div class="group">` per date bucket (Today / Yesterday / This week / Older)
- Each group: a thin `<div class="group-lbl">` band (mono 10.5px ALL-CAPS + horizontal divider + optional italic accent word in Instrument Serif) followed by content
- **Today group includes a hero card** (`.hero`) for the single most recent note, then `.rows` underneath for the rest
- Other groups: only `.rows`

**Hero card** (`.hero`):
- Two-column grid: content left, large arrow right (`56px` Familjen Grotesk, slides 8px on hover, recolors to orange)
- Eyebrow: 6px orange dot with soft glow + mono caps eyebrow text ("Research · świeże · 4 min temu")
- H1: Familjen Grotesk 500, `clamp(32px, 4.4vw, 52px)`, line-height 1.02, letter-spacing -0.035em, `max-width: 18ch`, `text-wrap: balance`
- Lead: Instrument Serif italic, 18px, muted, line-height 1.5, `max-width: 56ch`
- Meta line: mono 11.5px, items separated by 4px circular pips, includes thread (bronze color `#8b6535`), word count, theme name, and optional `★ FINAL` in orange
- Hover: background gradient `linear-gradient(180deg, transparent, var(--vbg-2))`

**Row** (`.row`):
- Grid: `88px minmax(0,1fr) 92px auto`, gap 18px, padding 12px 8px
- `border-bottom: 1px solid var(--vline-2)` (subtle)
- Hover: bg → `--vbg-2`, **plus** a 2px orange spine slides in from left via `::before` (transition .12s)
- Cols: `.type` (mono 9.5px ALL-CAPS, color-coded by type — see Type Colors below), `.title` block (Familjen 500 18px ellipsis + mono 11px sub-line with thread + theme/wordcount), `.age` (mono 11.5px right-aligned muted), `.stat` (final ★ orange, expiring ⏱ amber, neutral `·`)

**Group label** (`.group-lbl`):
- Display: flex, baseline-aligned
- Main label: mono 10.5px, letter-spacing 0.18em, ALL-CAPS, `--vmuted-2`, weight 500
- Count suffix: `--vmuted`, no caps
- `.spacer { flex: 1 }`
- Optional `.accent` element: Instrument Serif italic 15px in orange — used sparingly ("świeże" on Today, "w toku" on active threads). Don't add to every group; this is a visual rhythm device, not metadata.
- `padding: 0 4px 10px; border-bottom: 1px solid var(--vline)`

### 2. `/search?q=...` — results

Same chrome (top bar + filter strip), but inside `.v-page`:

**Section 1 — Threads** (cluster cards):
- `.cluster` — visually different primitive from `.row`. Solves brief pain #4.
- `padding: 18px 18px 18px 22px; background: var(--vbg-2); border: 1px solid var(--vline); border-radius: 12px`
- `::before` — 3px orange vertical bar at left, top/bottom inset 14px
- Two-col grid: content left, `.cluster-meta` right (column of mono lines + one big Familjen number, e.g. "5 / not / ★ final · 4 min temu")
- Inside content: mono uppercase thread id (bronze) → Familjen 22px h3 → 13.5px muted blurb (with `<mark>` for search hits) → `.stack` of mono chips for version history (`v5 final · 847w`, etc.). Chips marked `.final` get orange border/color
- Hover: border → orange, translateY(-1px)

**Section 2 — Notes** (`.row.with-snippet`):
- Same row primitive, but with a `.snippet` paragraph below the title — **Instrument Serif italic 16px**, muted, line-height 1.55, max-width 64ch
- `<mark>` inside snippet: `background: var(--vorange-soft); padding: 0 3px; border-radius: 2px; font-style: normal; font-weight: 500; font-family: var(--vbody)` — reads like a highlighter
- Score replaces the `.age` column: `★ 12.4` in mono

Both sections nested in `.group` blocks with their own `.group-lbl` ("Wątki" / "Notatki") so they're visually framed as separate.

### 3. `/threads`

Same chrome. Inside `.v-page`, `<div class="group">` per status bucket ("Aktywne" / "Zamknięte").

**Thread card** (`.thread-card`):
- Grid: `1fr auto auto`, gap 22px, padding `18px 8px 18px 30px`
- `::before` — 2px gray vertical spine at `left: 8px`, inset top/bottom 18px. **Hover turns spine orange.** This is the thread-as-axis metaphor.
- Content cell: mono caps thread id (bronze) → Familjen 20px title → `.progress` row
- `.progress`: row of 18×4px "ticks" (border-radius 2px). `tick.has` = note exists (`--vmuted`), `tick.final` = final note (orange). After 8+ ticks, replace remainder with `.more` ("8 wersji, brak final" in mono 10px)
- Count cell: huge Familjen number (28px) + mono 10.5px caps "NOT" below
- Latest cell: mono 11.5px muted right-aligned + optional `.final-marker` (orange "★ v5 final")

### 4. `/n/:id` — single note

**Two-column shell** (`.note-shell`):
- `grid-template-columns: 248px 1fr` (down from prod's 280px)
- Min-height `calc(100vh - 60px)`

**Sidebar** (`.note-side`, left column):
- Background `--vbg` (matches body)
- `border-right: 1px solid var(--vline)`
- Padding `24px 22px 22px`
- `position: sticky; top: 60px; max-height: calc(100vh - 60px); overflow-y: auto`
- Children order:
  1. `.back` link — mono 11px caps, hover → orange
  2. `.type-pill` — mono 9.5px caps badge, type-colored background (orange/blue/bronze)
  3. `<h1>` — Familjen 500, 24px, letter-spacing -0.025em, line-height 1.15, `text-wrap: balance`
  4. **`.action-card` — the primary CTA. Black background, hover → orange.** Padding `14px 16px`, border-radius 10px. Three stacked children (forced `display: block`): tiny mono caps eyebrow "PRIMARY ACTION" / Familjen 16px title with orange `★` glyph / mono 11px hint ("Zatrzymaj auto-delete · zarchiwizuj jako wersję kanoniczną wątku"). On hover, background → orange, translateY(-1px). This is the load-bearing fix for brief pain #3 — the action must read like a feature, not a footer button.
  5. `.side-meta` `<dl>` — 2-col grid: `auto 1fr`, gap `12px 14px`. dt = mono 9.5px caps muted, dd = mono 12px. Threads bronze, warn amber, final orange. Bordered top/bottom with 18px padding above/below.
  6. `.side-tags` chips — mono 10.5px, padding `3px 8px`, bg `--vbg-2`, border `--vline-2`, radius 4px
  7. `.side-aux` (margin-top: auto) — vertical stack of mono 11px text links (raw HTML / export / share / delete). Delete is `color: #c8412a; opacity: 0.7` — present but visually deemphasized

**Main column** (`.note-main`):
- Background `--vpanel` (#fdfcf9)
- Optional `.note-banner` if note isn't final — amber gradient strip, mono 11.5px text + a duplicate `.finalize-btn` on the right (black bg, hover → orange, white-space: nowrap, flex-shrink: 0)
- `.note-iframe` fills the rest: `width: 100%; height: calc(100vh - 60px); border: 0`
- **Wide chrome / narrow content rule:** the iframe panel is wide, but the *theme inside the iframe* enforces its own narrow `--wrap-max` (720–960px). So the visible reading column is narrow and centered, surrounded by wide neutral panel. **Do not change the themes' `--wrap-max`.** This was brief pain #2 and the fix lives entirely in viewer chrome (the panel widens), not in themes (which stay narrow).
- The mockup substitutes a static placeholder article (`.note-iframe-fallback`) because no server. Strip this in production — production renders `<iframe src="/raw/:id" sandbox="allow-same-origin">`.

## Interactions & Behavior

- **Search input** (`.v-search`): focus-within state → border orange + `box-shadow: 0 0 0 4px var(--vorange-soft)` + background white. Always sticky in top bar. `/` keyboard shortcut focuses it.
- **Filter pill** (`.fp`): active state inverts (`background: var(--vink); color: var(--vbg)`). Warn variant inverts to amber. Hover transitions color/border .12s; `:active { transform: translateY(1px) }`.
- **Top nav** (`.v-nav a`): active link gets a 2px orange underline 4px below baseline via `::after`.
- **Row hover** (`.row:hover`): bg → `--vbg-2` AND 2px orange spine slides in from left (`.row::before` background transition).
- **Hero hover**: subtle gradient bg + arrow translates 8px right + recolors to orange.
- **Cluster hover**: border → orange, `translateY(-1px)`.
- **Thread card hover**: spine recolors to orange.
- **Action card hover**: bg → orange, `translateY(-1px)`.
- **Finalize button hover**: bg from black → orange.

All transitions .12–.15s. **No layout-shifting transitions, no spring physics, no large-scale animations.** This is editorial, not Stripe.

## Mobile (≤ 860px)

- `--gutter` shrinks to 18px
- Top bar: nav wraps to a second row (order: 3, width: 100%); divider + tagline in logo hidden; search input takes full width
- Filter strip: `overflow-x: auto; flex-wrap: nowrap; padding-right: 24px`; pills become flex-shrink-0; `.results-meta` hidden
- Hero: single column, arrow hidden, h1 → 32px, lead → 16px
- Row: grid `64px minmax(0,1fr) auto`, gap 12px; `.age` hidden (use sub-line for time); title allows wrapping
- Cluster: single column; meta moves below blurb as a row
- Thread card: 2-col grid; latest column to position 2; progress wraps to a third row spanning full width
- Note shell: single column; sidebar (`.note-side`) goes static (not sticky), border-right removed, border-bottom added

## State Management

The viewer is **server-rendered, stateless**. There is no client-side state machine. Each route is a separate Bun.serve handler emitting fresh HTML.

What the prototype's `route()` JS function emulates corresponds to **server navigation** in production. Do not port that JS.

Minimal client JS that **should** ship (≤ 30 LOC):
- `/` keypress → focus search input
- Optional: search input `esc` → blur + clear

No state needed beyond that. No localStorage. No SPA routing.

## Assets

- **Fonts only.** All from Google Fonts CDN via the `@import` at the top of `viewer.css`. No icon font, no SVG asset files.
- **Emoji** used inline as iconography: `⌕` (search), `★` (final), `⏱` (expiring), `📂` (thread), `←` `↗` `✕` `·`. These are intentional — the brief allows them and they keep the bundle to zero binary assets.

## What NOT to change

- **`themes/*/theme.css`** — leave all 8 themes alone. Theme content rendering is out of scope.
- **`themes/*/theme.md`** — content guidelines for agents, not for the viewer.
- **Storage, MCP, API endpoints** — work as-is.
- **The wordmark lockup** — v08 (Familjen 500 `folio.` + thin divider + JetBrains Mono caps tagline) is final. The CSS preserves it exactly.
- **`folio export --standalone`** — uses themes, not viewer chrome. Unaffected.

SQLite FTS5 + polskie diakrytyki

unicode61 remove_diacritics 2 jako tokenizer w FTS5 sprawia, że polskie diakrytyki normalizują się przed indeksowaniem. Skutek: query swieze matchuje świeże bez dodatkowej infrastruktury.

CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, headings, body, tags,
  tokenize = 'unicode61 remove_diacritics 2'
);

Domyślny porter stemmer to angielski — bezużyteczny dla PL. unicode61 bez stemmera + diacritics removal to optymalny baseline. Dla pełnego stemming PL trzeba własnego tokenizera (post-MVP).

Gotcha: hyphen jest separatorem domyślnie. „Fine-Tuning" indeksuje się jako dwa tokeny: fine + tuning. Query musi to odzwierciedlać — dzielić na hyphenie też, nie tylko whitespace.

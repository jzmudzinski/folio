SQLite FTS5 + diacritics

unicode61 remove_diacritics 2 as the FTS5 tokenizer makes diacritics normalize before indexing. Result: the query swieze matches świeże, cafe matches café, with no extra infrastructure.

CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, headings, body, tags,
  tokenize = 'unicode61 remove_diacritics 2'
);

The default porter stemmer is English-only — useless for most other languages. unicode61 without a stemmer + diacritics removal is the optimal baseline. For full per-language stemming you need a custom tokenizer (post-MVP).

Gotcha: hyphen is a separator by default. "Fine-Tuning" indexes as two tokens: fine + tuning. Your query needs to mirror that — split on hyphen too, not just whitespace.

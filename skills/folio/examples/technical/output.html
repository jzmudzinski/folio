ADR-001: Bun zamiast Node dla Folio

Wybór runtime CLI + MCP server + viewer. Status: Accepted

Kontekst

Folio = CLI + lokalny HTTP server (viewer) + stdio MCP server. Trzy komponenty muszą startować szybko (CLI < 50ms dla user feel) i obsłużyć Bun:sqlite + sanitize-html + @modelcontextprotocol/sdk.

Decyzja

Bun + TypeScript jako runtime.

Dlaczego

  • Startup time: ~10ms (Bun) vs ~80ms (Node). User feel CLI >> ⭐.
  • Native sqlite via bun:sqlite — zero native bindings, działa cross-platform.
  • Zero build step — TypeScript natywnie. CI/CD prostszy.
  • Bun.serve + HTMLRewriter — wbudowany HTTP server + Cloudflare-style HTML streaming, szybsze niż jsdom.
  • Bun test wystarczy — nie potrzeba Vitest/Jest.
  • MCP SDK (@modelcontextprotocol/sdk) jest TS — walidowane że działa na Bun 1.3.13 (smoke test).

Tradeoffy

  • Mniejsze community niż Node — ale rośnie szybko, większość npm packages działa.
  • Niektóre paczki z natywnymi bindingami mogą wymagać kompilacji — sprawdzamy ad-hoc.
  • Production maturity wciąż < Node, ale dla single-user CLI/local server akceptowalne.

Alternatywy odrzucone

  • Node.js + tsx/ts-node: wolniejszy startup, więcej setupu, gorszy DX. Rozważymy jako fallback gdyby Bun zawodził pod konkretne deps.
  • Deno: świetny dla nowych projektów, ale npm interop kuleje przy MCP SDK i niektórych transitive deps.
  • Rust: overkill na MVP. Możemy przepisać hot-paths (sanitizer, FTS) gdy będą bottleneck.
  • Go: mniej idiomatic dla naszego async/streaming work; brak natywnego HTML sanitizera porównywalnego z sanitize-html.

Konsekwencje

  • Wymóg: Bun ≥ 1.3 zainstalowany u usera. Install: brew install oven-sh/bun/bun (lub curl -fsSL https://bun.sh/install | bash).
  • Cross-platform: macOS / Linux działają out-of-the-box. Windows via WSL2 (Bun Windows native jest beta).
  • Plan B (jeśli Bun + jakaś paczka zawiedzie): port do Node 20+ jest mechaniczny, ~1 dzień roboty. Większość kodu (TS) przenosi się 1:1, zamieniamy bun:sqlite na better-sqlite3.

Werdykt

Bun + TypeScript stoi. Plan B (Node fallback) udokumentowany. Walidacja MCP SDK na Bun przeprowadzona w S0 — wszystkie 8 tools'ów Folio MCP działa.

ADR-001: Bun over Node for Folio

Runtime choice for the CLI + MCP server + viewer. Status: Accepted

Context

Folio = CLI + a local HTTP server (viewer) + a stdio MCP server. All three must start fast (CLI < 50ms for user feel) and handle Bun:sqlite + sanitize-html + @modelcontextprotocol/sdk.

Decision

Bun + TypeScript as the runtime.

Why

  • Startup time: ~10ms (Bun) vs ~80ms (Node). User feel for CLI >> ⭐.
  • Native sqlite via bun:sqlite — zero native bindings, works cross-platform.
  • Zero build step — TypeScript runs natively. CI/CD is simpler.
  • Bun.serve + HTMLRewriter — built-in HTTP server + Cloudflare-style HTML streaming, faster than jsdom.
  • Bun test is enough — no need for Vitest/Jest.
  • MCP SDK (@modelcontextprotocol/sdk) is TS — validated to work on Bun 1.3.13 (smoke test).

Tradeoffs

  • Smaller community than Node — but growing fast, most npm packages work.
  • Some packages with native bindings may need compilation — we check ad-hoc.
  • Production maturity is still < Node, but acceptable for a single-user CLI / local server.

Alternatives rejected

  • Node.js + tsx/ts-node: slower startup, more setup, worse DX. We'd consider it as fallback if Bun failed for specific deps.
  • Deno: great for new projects, but npm interop is shaky with the MCP SDK and some transitive deps.
  • Rust: overkill for MVP. We can rewrite hot paths (sanitizer, FTS) when they become bottlenecks.
  • Go: less idiomatic for our async/streaming work; no native HTML sanitizer comparable to sanitize-html.

Consequences

  • Requirement: Bun ≥ 1.3 installed on the user side. Install: brew install oven-sh/bun/bun (or curl -fsSL https://bun.sh/install | bash).
  • Cross-platform: macOS / Linux work out-of-the-box. Windows via WSL2 (native Bun Windows is beta).
  • Plan B (if Bun + some package fails): porting to Node 20+ is mechanical, ~1 day of work. Most code (TS) moves 1:1; replace bun:sqlite with better-sqlite3.

Verdict

Bun + TypeScript stays. Plan B (Node fallback) is documented. MCP SDK validation on Bun was done in S0 — all 8 Folio MCP tools work.
